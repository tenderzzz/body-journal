# 0.5.0 使用与升级说明

本轮主要完善记忆可靠性、饮食估算依据和数周趋势核对。保留轻量记录和按需分析，记忆整理不额外调用后台模型。

## 记忆如何生效

“我的档案”可展开每条记忆的来源与修改历史；回答下方可查看本次使用的内容、版本和有效时间。明确表达的偏好继续自动保存并提供撤销。已知主题的相反表达更新原条目；不同对象通过主题和对象区分。含义不明确的信息仍需补充，不能保证本地规则理解所有自然语言。

临时状态有期限，推断保留待确认标记。到期表示需要重新确认，不代表疼痛或不适已恢复。相关身体限制优先参与训练分析。长期信息、结构化模板和食物标签也受检索预算约束，模型不能把未带入的信息说成已检查。

更正记忆后，依赖旧版本的回答会标为过时，退出后续上下文。历史分析使用当时适用的版本。旧档案无法还原的原话、时间或证据保留“未知”，不会补造。

## 饮食如何修正

常用食物支持明确的产品名称、品牌、口味、规格与别名。品牌相同不等于同一个产品；别名应只指向同一产品。标签可按 g、ml 或份填写，只有已知密度时才跨质量和体积换算。

记录详情的“补充／修正食材和分量”支持实际食用比例、原始单位、分量依据及本餐标签。点击“保存并重新计算”生效。这些更正及移除项会跨重新分析、原文修改、重启和备份恢复保留。更正常用产品标签需明确编辑常用食物，本餐更正不自动改成长期模板。

明确的本餐标签或手动修正优先于旧标签。图片标签保留识别文字及原图关联，仍需要核对 OCR；系统没有验证标签是否正确识别。缺少可靠来源的估算不会因为重复出现自动变成称量结果或完整包装标签。混合菜采用整菜或拆分原料时，通过菜品分组避免重复计算已含用油。

## 固定步数基准与趋势

参考步数与对应日常基线按生效日成对固定。每日步数仍动态修正，滚动历史中位数作为更新建议，采纳时保存新版计算资料。升级当天保持旧参考，之前的日期保留原算法。来源变化会提示核对固定快照。

训练明细展示 App 与公式估算，并指出实际采用项。四周核对表展示体重中位数、完整饮食天数、摄入与活动来源。这里不估计真实代谢，不根据单日体重波动自动调整目标；现有三周记录条件继续用于目标讨论。

## 备份与精度评测

数据库和完整备份升级到 v4。升级前自动保存备份，支持恢复 v1、v2、v3；旧版应用不能打开 v4 档案。请使用应用导出和恢复，不直接替换 SQLite 文件。

“连接与数据 → 精度评测”可保存合成示例，或主动选择自己的 JSON 参考文件，在本机计算食物匹配、热量／蛋白质误差、区间覆盖、重复波动和追问次数。入口不会自动发送照片或调用付费模型。详见[评测说明](精度评测.md)。

自动测试使用合成数据与模拟响应，验证软件行为。真实照片识别与个人能耗误差需要另行收集可靠参考；本轮不承诺固定的精度提升百分比。
