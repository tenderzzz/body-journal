BODY JOURNAL / v0.5.1

身体的变化，从一点线索开始。

手机负责随手记录，Mac 把记录连成持续更新的个人档案。

v0.5.0：记忆、饮食与趋势

档案中可展开记忆来源和历史版本，回答下方可查看使用的记忆。过期或更正会让旧回答失效；状态到期不表示身体已恢复。常用食物支持克、毫升和份，本餐可修正食用比例与标签，并跨重分析保留。步数参考与日常基线固定为有生效日期的快照，滚动历史改为更新建议。能量页增加四周核对，连接与数据新增本地精度评测。升级前自动备份，新格式为v4，可恢复v1–v3。真实照片识别和个人能耗精度仍需可靠样本验证。

第一次打开

  1. 打开身体手记。先去“我的档案”检查目标和已知偏好；能量、蛋白质目标可以暂时留空。
  2. 进入“连接与数据”，点击 Continue with ChatGPT，在官方页面完成登录和订阅额度授权。返回应用后选择账号提供的模型，保存连接设置。
  3. 点击测试图文连接。应用只发送自带的测试图；成功后可以开始解析照片和提问。
  4. 如果选择 DeepSeek，输入 API 密钥、填写美元月预算，保存密钥和连接设置。默认预算为 0，不会发起付费请求。

账号资格和可用模型以官方返回结果为准。登录不会导入你原来的 ChatGPT 对话或记忆。没有连接 AI 时，保存记录、训练格式解析、趋势、手动修正和备份仍然可用。

把四个入口放到 iPhone

  1. Mac 的“连接与数据”中点击建立并打开收件箱。默认是 iCloud Drive 中的 Shortcuts/BodyJournal/inbox。
  2. 本仓库不含签名版：先用 python3 scripts/build-shortcuts.py 生成源文件，再用自己的 Apple 账号 shortcuts sign --mode anyone 签名（详见仓库 README）。然后在 iPhone“文件”中找到保存项目的位置下的 shortcuts 文件夹，分别点开四个已签名 .shortcut 文件。也可以从 Mac 将这四个文件 AirDrop 到手机。
  3. 每个安装页面都会问保存位置，统一选择上述 inbox 文件夹。不要选源码中的 unsigned 文件夹。
  4. 添加完成后，可在快捷指令详情中“添加到主屏幕”。照片与训练文字也可以从系统分享菜单传给对应快捷指令。
  5. 先运行“随手记”写一句测试文字；看到“已保存”后，在 Mac 打开身体手记，约 20 秒内自动检查，或手动点同步。确认这条记录出现。

快捷指令不需要 Mac 开机。手机先写入本机 iCloud 文件夹，等网络恢复后由系统同步。成功提示表示本机已保存，不代表另一台设备已收到。取消输入、文件保存失败时，不会显示成功。首次使用需要你按系统提示选择相机、照片或文件夹权限。

入口怎么记录
记一餐选择“拍照记餐”或“只记文字”。文字模式写菜名和大概分量，也可用系统听写，无需照片；从分享菜单传入图片仍可直接记录。空白文字不会保存。首版每次取第一张图片。
记训练选择训练文字或 Keep 截图，可补感受。分享多张图片时首版取第一张。
记身体选择体重、腰围或两项。体重用 kg，腰围用 cm。
随手记写睡眠、疲劳、压力或安排；可用键盘自带听写。

把过去的训练带进来

在“记录”页面选择“导入笔记”。每次训练前放一个独立的日期行，先预览再导入：

2026-10-20
卧推 60kg 3组×8次
哑铃划船 单手 20kg 3组×10次
感受：最后一组有些吃力

2026-10-22
卧推 62.5kg 3组×8次

示例数值只用于说明格式。没有时间的历史笔记默认当天中午 12:00（上海时区），可在详情修改。保留原有记法也能先保存；像“3×8”或未说明单手/总重的哑铃记录会等待你确认，避免直接进入错误统计。

分析、追问和修正

新增餐食和文字笔记会显示待分析。点击“分析新记录”或进入单条详情分析。AI 整理训练和食材，数值统计由本地程序计算。餐食结果包含营养来源、分量范围、主要假设和估算依据。

补充追问时，在记录详情修改原文并重新分析；也可以直接调整食材分量或训练组次。旧答案会显示“依据已变化”。助理回答旁的依据可点开原始记录，查看照片与修订历史。

可试着问：“最近几周训练怎么样？”“我已记录的餐食有什么可以调整？”“还需要补充哪些记录才能判断进展？”记录少、漏餐或分量不清楚时，回答应说明证据不足。体重和腰围变化本身不能证明肌肉或脂肪变化的原因。

日历、动作与首页对话

首页日历固定在聊天区顶部（不再随聊天滚动），默认一周，可左右滚动、切换前后周或回到今天；“展开月历”可按月浏览。点击日期打开当天记录，返回首页保留浏览位置。没有记录的日期显示“暂无记录”。

“趋势 → 训练表现”按标准动作名集中展示。哑铃动作统一按单只重量、杠铃与史密斯按报告总重、器械按器械标重统计，同一动作不再按口径拆成多份；哑铃肩推统一按坐姿统计；原文明确写“总重/双手合计”时保留总重。动作按胸、背、肩、腿、核心分区显示；点击“整理动作名称”可统一同义名称、手动指定计重口径、归档或取消归档动作、删除手动归类。删除训练记录可在训练表现表格行末点删除，在“记录”页勾选“显示已移除的记录”可恢复。改名后点击“保存此项”，或在底部点击“保存全部并关闭”；成功后显示“已保存”，失败原因会留在弹窗中。手动名称优先保留。轮次、递减档位和单手口径在组数据中保留。歧义动作需要你指定归类。

在首页直接说“以后每次最多练60分钟”或“更正一下……”，助理会按你的明确表达更新记忆；保存成功后显示回执，可撤销。首页粘贴训练日志只作讨论，点击“去记训练”才入档；不会直接改变训练进度。“本周复盘”由你点击触发，输出总结、滚动计划和调整重点。

“我的档案 → 个人执行规则”可查看和编辑完整训练、恢复与沟通规则。历史身高、体脂和既往不适只作参考，近期有日期的实际记录优先。

补记日期与按日查看

原文以“2026.10.20”“10月20日”或“昨天午餐”注明实际日期时，保存或补充记录后自动归到发生日。没有具体时刻时暂记当天12:00，并在详情标注。手动选择的日期优先保留。首页最近七天的日期可以点击，进入当天记录；记录页也可直接选日期或清除筛选。

常用食物与补剂

蛋白粉、肌酸等长期复用的包装食品，可以在“我的档案 → 常用食物与补剂”里添加：填写名称、品牌口味（可选）、每份克数和每份的能量/蛋白质/碳水/脂肪。之后分析餐食时，只要食材名称与它一致，营养就按包装标签在本地计算，并在记录里注明来源。也可以在首页直接说“记住我的补剂是……每份 30g、能量 120kcal、蛋白质 24g、碳水 3g、脂肪 1.5g”，或“加一个常用食物：……每100g……”；四项齐全时会自动结构化（每100g数据按每份100g处理），不需要“记住”字样；缺少项目时会先追问。同一种食材累计出现在至少两餐时，应用会在常用食物区给出候选卡片，只有你点“加入常用食物”后才会保存；来自模型估算的候选会标注“建议核对包装”。品牌也会参与匹配。

记一餐时引用过去的一餐

记录一餐时可以直接写“和 10 月 20 日午餐一样”或“照旧/和上次晚餐一样”。分析时会从最近 90 天的餐食记录里找到那一餐，整份复制食材与分量，再按当前食材库重新计算营养；记录详情会显示“复制自某天某餐”。同一天有多餐或找不到时会先追问，不会猜。复制后仍可在记录里微调分量。

记忆怎么更新

首页对话和每次分析都会自动更新记忆：对话里明确陈述的长期信息（偏好、条件、记法、补剂标签）会直接保存，临时状态写入带期限的短期记忆；分析餐食或训练时，记录原文里明确写出的补剂标签或长期偏好也会自动提取。每条自动记忆都必须有你的原话或记录原文作为依据，数字也必须出现在依据中；记录详情会显示“分析时自动记住”，可在“我的档案”查看、修改或撤销。明确表达的训练、饮食偏好会自动保存。已确认的动作重量、组数和次数会形成持续更新的训练参照；同款餐食在至少两天出现后，自动记住食材和最近分量。可在“我的档案”查看依据、修改或停用。手动改写后由你管理，系统不覆盖；停用后不会因新记录自动恢复。这些参照参与后续分析，但不是固定训练目标，也不会直接替你新增摄入。

“我的档案”的长期信息按主题分组（饮食与环境、记录习惯与记法、沟通偏好、训练规则、健康限制、其他）；同一主题再次保存会更新原条目而不是新建。“我的档案”分为长期信息、常用食物与补剂、训练参照与常吃餐食、最近状态和待验证判断。你可以添加、编辑、停用或撤销；近期状态可以设置结束日期。模型从记录提出的状态带“待确认”，推断保留判断标记。修改依据后，相关记忆会标为过期，需重新确认。

“我的档案”右上角的“整理记忆”会先自动完整备份，再删除失效的自动训练参照、过期或失效的状态/判断，停用与常用食物重复的营养标签，并合并完全重复的记忆；训练参照默认只显示 8 条，可展开全部。整理不会动你的原始记录。对话中的你自己的话可以点“记到档案”，确认内容和时间后保存。新建对话只清空当前对话上下文，历史消息保留在本地导出中，个人档案和记录不变。

能量：看懂每天的吃与动

v0.5.0：当天步数会动态调整日常消耗，参考步数与对应基线按生效日期固定保存。平常非训练步数可留空：优先使用手填参考，其次使用此前28天至少7个完整记录日的中位数，历史不足时使用明确标注的档位暂定范围。保存计算资料时固定所选参考；此后的滚动历史只提供更新建议，不会静默改变计算基准。暂定范围是产品假设，可保存新版资料更正，不代表个人实测值。

“步数怎样计入”显示全天步数减去跑步步数的过程。优先用跑步记录报告的步数，其次用明确平均步频×运动时长推导；暂停时间不参与推导，冲突时长不使用。可以打开原记录更正数据。半天数据或跑步重叠不明时，暂不调整全天日常消耗。

在“当天补充”填写步数、范围和覆盖时间；更多选项中可以选择截图来源、填写实际非训练步行距离或更改活动档位。手动输入优先于截图。保存后更新计算结果并保留活动确认，原始记录变动后需重新核对。饮食目标保持稳定。

跑步App的活动热量和总热量分别计算，标签含糊时保留原值、暂用公式。相同截图只计一次，疑似重复会提示核对。记录详情可“核对 / 更正活动数据”，支持修改或清空错误字段；重新提取保留手动更正。来源修改后需重新确认活动已记齐。

打开“能量”，先补充计算资料并核对常规训练安排。填写区域可以单独滚动；底部“我已核对资料”和“保存计算资料”始终显示，勾选核对后即可保存。体重沿用“记身体”的测量；默认今天生效，也可选择适用的历史起始日期。日常基线结合静息公式和活动档位，训练只加超出同期基线的部分。当天显示全天预计，不是截至此刻已消耗的热量。展开“计算方法、假设与缺失项”可查看每一项的来源和假设。

点击“设置目标”，选择维持、减脂或增肌，确认一个相对稳定的每日热量与蛋白质目标。已有手填目标会保留，选择“填入参考数值”再点“确认目标”才会替换。专门训练缺少时长时采用已确认的常规范围，不会把假设写成实际记录；力量和跑步时长请分别写清楚。跑步截图已经识别出实际结果时，无需在备注重复输入距离和时长；旧版“无补充”图片记录也可直接计入，明确计划、取消或待确认的记录仍不计入。

当天饮食和活动核对后，可勾选“已记齐”并保存。漏餐、未分析食材、未确认训练不会按零处理；记录修改后需重新核对。只有资料完整时才判断参考缺口或盈余，区间跨零时显示无法确定。主数值按50 kcal取整；参考区间不是置信区间或实测消耗。

“今天怎么吃”“下一次怎么练”“目标需要调整吗”由你点击提问。数值调整要求同一目标完整执行21天、至少15天饮食记齐且三周每周有3个体重记录日；单次最多100 kcal，采纳后次日生效，至少间隔14天再调整。依据变化或跨日后，旧草案需要重新生成；目标修改可撤销，保留历史生效记录。打开页面不会自动调用模型。

升级前自动备份，完整备份格式为v4，仍可恢复v1／v2／v3旧备份；旧版本应用不能直接打开升级后的数据库。详细方法见能量估算说明。

数据导出和恢复

“连接与数据 → 导出可读资料”生成 Markdown、JSON 和原始照片。“保存完整备份”还保留对话、修订历史、记忆与配置；模型密钥不在备份里。恢复时会先在本地 vault/backups 保存当前档案，再恢复选择的备份，保留本机收件箱路径。

主档案：~/Library/Application Support/BodyJournal/vault。不要直接把运行中的数据库放进 iCloud。完整备份上限 512 MB，大档案可使用可读导出。备份包含健康资料，请放在自己控制的位置。

常见情况

  • 手机显示保存成功，Mac 没出现：检查两端的 iCloud Drive 同步、收件箱是否一致；在 Mac 点击同步，展开同步提示查看原因。
  • 显示等待附件：原文件还没同步完整，应用会重试；不会先把残缺记录计入统计。
  • 模型断流或额度不足：原始记录和问题都保留。重新连接或稍后重试，应用不会自行启用另一个付费渠道。
  • 营养值偏离直觉：查看食材是生重还是熟重、估计分量和油量；未匹配食材按同类食品估算计入，补充标签或分量后可修正。
  • 想先体验：使用项目的“查看示例.command”，窗口会标明独立示例档案。
