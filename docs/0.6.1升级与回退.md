# v0.6.1 升级与回退

餐食、训练、身体与随手记按档案时区每天 04:00 换日。步数按自然日 00:00 换日。例如 11 月 3 日 01:20 的夜宵归入 11 月 2 日手记，详情显示实际发生时刻。凌晨问摄入与步数时，助理分别标明两者的日期。

能量日报采用同日期手记的饮食、训练与自然日步数修正。凌晨跑步计入前一个手记日的训练，跑步步数从实际发生的自然日总步数中扣除。跨零点跑步只有全程总步数时，相关日期提示核对步数重叠，训练结果仍可查看。

## 升级

1. 退出旧应用，安装 v0.6.1。首次启动会在原档案目录外生成 `vault-before-v061-…`，内含旧格式数据库、原文、图片与校验清单。校验通过后，数据库升级为 v6，备份容器格式为 v5。
2. 已有凌晨记录按四点重新归日。到“连接与数据 → 日期与历史归属”查看移动清单并打开原记录，复核来源发生变化的饮食和活动记齐状态。手填步数按原自然日保存。
3. 记录详情显示实际日期、钟点与手记归属日。能量页可在凌晨单独填写新自然日步数。“本周”的临时安排到下周一 04:00 结束。

升级在本机完成。原文、图片、发生时间、每餐的营养估算与固定目标均可与回退副本核对。模型调用由正常分析或提问发起。已有回答保留原文和当时保存的依据。

## 备份与回退

- 使用“保存完整备份”生成 v5 `.bodyjournal`。本版可以恢复 v1–v4 JSON 与 v5 SQLite 备份，恢复后的档案采用四点归日。
- 回退前先将升级后新增的数据保存为独立 v5 备份，然后退出应用。将升级前副本中的完整档案恢复为主档案目录，并安装配套的 v0.6.0 应用。旧版通过它自己的旧格式档案恢复使用。
- 自动回退点位于主档案旁。直接安装时另保留旧应用与完整安装前副本。保留这两类副本直到日常使用核对完成。

## 收件箱与历史查询

应用运行时监听收件箱，遇到下载未完成的 JSON 或图片会等待并退避重试。启动、唤醒、手动检查和定期补扫会找回遗漏。“连接与数据”可查看最近同步状态、失败原因和重试次数。

记录每页 50 条，对话每页 30 条，可继续加载。历史引用按编号直接打开原文。日志、回退件、安装包、密钥和健康档案在本机保存，公开源码使用合成测试数据。
