# 身体手记 · iPhone 客户端与 iCloud Drive 双向同步实施计划

2026-11-21 · 基线 v0.6.17 · 个人自用，一台 iPhone 和一台 Mac · 待实施

**目标体验**是在 Mac 合盖时用 iPhone 离线记一餐、附上照片。晚上打开 Mac 能看到这条记录，把米饭从一碗改为半碗。下次打开手机，原来那条记录就显示半碗，照片还在。整个过程只在首次设置时选一次文件夹，日常使用无需导入、导出或同时打开两端。

采用独立安装的 iPhone App、现有 Mac App 和用户选择的 iCloud Drive 文件夹。AltStore Classic 搭配 Mac 上的 AltServer 负责安装与续签，文件夹由系统「文件」授权给 App。这样可以用免费开发者账号实施，省去申请专属 CloudKit 容器。首个真机原型预计 **2–3 人日**，可试用版本累计 **15–23 人日**，约合一人全职 3–5 周。[苹果目录授权](https://developer.apple.com/documentation/uikit/providing-access-to-directories) · [CloudKit 开通条件](https://developer.apple.com/documentation/cloudkit/enabling-cloudkit-in-your-app)

## 一、首版交付什么

| 场景 | 首版行为 |
| --- | --- |
| 手机上随手记 | 提供记一餐、记训练、记身体、随手记、记步数五个入口。餐食沿用最多 8 张照片，身体记录支持体重、腰围和体脂率，步数先手填。断网也能保存并重新打开。 |
| 换设备接着改 | 两端都能浏览、改文字和发生时间、软删除、恢复选入同步的记录。在 Mac 修正的餐食份量能在手机详情中看到。历史记录沿用原编号和照片顺序，手机从选入时的版本开始显示更新，选入前的修订仍可在 Mac 查阅。 |
| 看同步进度 | 显示「已存本机」「待发送」「已写入共享文件夹」「另一台设备已接收」。权限失效、附件未到或两端有冲突时给出具体操作。打开 App、回到前台或点「立即同步」均能补传。 |
| 继续用现有 Mac 功能 | AI 分析、能量趋势、历史复盘仍在 Mac 使用。用户明确修正的份量进入同步字段。手机首次试用以录入、时间线和记录详情为主。 |

**哪些数据会进入 iCloud。** 原型只使用合成餐食和测试图。苹果 App Store 审核指南 5.1.3(ii) 限制 App 把个人健康信息存入 iCloud，免费 Xcode 协议将 HealthKit 接口限于内部开发与测试。个人侧载不经过商店审核，所以上述审核条款与个人文档交换需要区分。选取文件夹和加密本身也不会扩大数据使用权限。[苹果审核指南](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research) · [Xcode 与 Apple SDK 协议](https://www.apple.com/legal/sla/docs/xcode.pdf)

首版将体重、体脂、步数和可识别个人的运动截图默认仅存本机。启用真实目录前，按来源、内容和用途列明允许传输的字段，照片随记录处理，用户可预览和选择。若完整健康档案不适合经 iCloud 传输，可沿用同一变更格式做两台设备配对直传。这个备选需要两台设备同时可互通，另行估时。

## 三、交付顺序与投入

以下按一名熟悉现有代码的开发者估算，包含开发和回归。真机原型可以单独交付，确认日常摩擦可接受后再投入余下工时。

| 阶段 | 投入 | 交付与完成条件 |
| --- | --- | --- |
| 1 · 两台真机跑通 | 2–3 人日 | 两端用同一 iCloud 账号开启 iCloud Drive。在 Mac 配好完整 Xcode 和 iOS SDK，生成真机 IPA，经 AltStore 安装。在 iPhone 的「文件」中选好测试目录，重启验证授权。用合成餐食和一张图走通手机新增、Mac 更正、手机回读。手动续签一次，再核对目录、本地记录和照片。 |
| 2 · 可靠地交换修改 | 4–6 人日 | 建立两端共用的变更格式、持久待发队列和收件回执。接入本地数据库、文件协调和附件校验。用两套隔离档案验证断网、重放、乱序、同时编辑、删除与恢复。 |
| 3 · 接上日常入口 | 4–6 人日 | 完成五种手机录入、日期时间线、详情和同步状态。接上 Mac 正常编辑入口和旧快捷指令。用 Mac 的实际食材编辑器更正份量，手机能看到修正值。手机拍摄的 HEIC 在导入时转换为 Mac 校验器支持的格式，并核对方向与张数。 |
| 4 · 加密、迁移和试用 | 5–8 人日 | 完成共享目录的应用层加密、设备配对和恢复密钥。把一组已有样例选择性迁入，验证中断续传、换机恢复和停用回退。两端试用覆盖一个完整的 7 天续签周期，记录自动刷新和手动恢复的实际结果。 |

开发者年费按 **¥0** 预算，方案使用已有的 iCloud Drive，不需要独立同步服务器。附件会占用自己的 iCloud 配额，空间不足时可清理或按自己的用量扩容。免费签名到期后 App 会暂时打不开。若 AltStore 本身也已过期，先用 AltServer 覆盖安装 AltStore，再刷新身体手记。一个完整续签周期是日历时间，可与后续开发重叠。首次配对、手机授权和真机复查需要机主在场。[苹果免费开发账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account) · [AltStore 刷新说明](https://faq.altstore.io/altstore-classic/your-altstore) · [AltServer 恢复说明](https://faq.altstore.io/altstore-classic/altserver)

当前开发环境选用 Command Line Tools，尚未检测到 `iphoneos` SDK。第一阶段从完整 Xcode 能构建真机包开始验收。

## 四、同步具体怎么做

1. **一次选目录，之后自动补传。** Swift 使用系统目录选择器保存授权书签，后续访问时重新解析，并通过 `NSFileCoordinator` 协调文件读写。Mac 和 iPhone 绑定同一档案标识，避免换账号或选错目录时把两个档案合并。撤销权限后仍可本地记，重选原目录即可继续。日常同步只需设备各自联网。续签时手机需能通过同一 Wi-Fi 或 USB 连上运行 AltServer 的 Mac，校园网若隔离设备可用 USB。[苹果目录授权文档](https://developer.apple.com/documentation/uikit/providing-access-to-directories) · [AltServer 连接条件](https://faq.altstore.io/altstore-classic/altserver)
2. **每次用户更改产生一份独立文件。** 为变更保存协议版本、档案标识、唯一操作编号、记录编号、父操作编号、动作和允许同步的内容。首次创建没有父操作。后续更改引用自己编辑时看到的版本。记录和待发操作在同一本地事务中提交。对端把写入记录、登记已处理编号放入同一事务，成功后再写回执。重复扫描或崩溃后重试只生效一次，收到的更改也不会绕回去反复发送。旧客户端遇到未知格式时保留待处理文件并提示升级。
3. **照片可以晚于文字抵达。** 同一张附件只传一份，引用放在记录里。文件先在本地暂存、校验大小和哈希，再发布到共享目录。收件方缺图时可先显示文字和「照片下载中」，补齐并核验后才确认完整接收。iCloud 占位文件、文件名变体或设备暂时看不到文件均不触发业务删除。锁屏前未发完的内容在下次回到前台时接着发。
4. **两边改同一条时，保留两个版本。** 来自同一父操作的不同更改进入冲突列表，显示两端的文字、时间或份量。选择一版或手动合并后，写一条同时引用两个父版本的操作。先收到子操作就等待父操作。软删除也有独立操作，删除和修改撞在一起时保留两份供处理，只有显式恢复才重新展示已删除记录。
5. **首次迁移和回退都有可核对的结果。** 先在隔离档案恢复一份本地备份，核对样例记录数、原编号和附件哈希。正式启用时由 Mac 为选定范围生成初始版本，记录导出起点，导出期间的新修改排进待发队列。旧收件箱重复送达、迁移中断重跑都按原编号去重。停用同步后，两端仍可读本地资料并保留未发更改。从旧备份恢复时先核对档案标识和两端版本，避免将旧快照当成新修改批量发出。[当前备份与恢复行为](privacy.md)
6. **可同步的真实文件在离开本机前加密。** 每个档案使用随机密钥，在第二台设备当面扫码配对，两端将密钥保存在各自的本机钥匙串。变更与照片用标准认证加密，文件名使用不含姓名或餐食内容的标识。恢复密钥单独保管，重新安装后能解密样例再接入。仅本机保存的敏感文件需核对系统备份排除设置。共享目录的加密只覆盖同步副本。目前 Mac 数据库和 v5 本地备份均无应用层加密。[CryptoKit](https://developer.apple.com/documentation/cryptokit/aes/gcm) · [系统备份排除设置](https://developer.apple.com/documentation/foundation/urlresourcekey/isexcludedfrombackupkey)

## 五、真机验收清单

全程使用合成样例和隔离档案。第一阶段先验餐食往返、重启和手动续签，后续阶段再验密钥、覆盖升级及一周自动续签。每次都记录两端版本、实际结果和失败时的恢复方式。

| 操作 | 通过条件 |
| --- | --- |
| Mac 合盖，iPhone 断网记餐附图，杀掉 App 后重开。两台设备先后联网，Mac 再修改份量。 | 手机重新打开后草稿已成为一条本地记录。Mac 收到同一编号和图片。手机随后显示修订后的半碗，记录总数仍为 1。 |
| 用同一账号和 App 标识刷新签名，再做一次版本覆盖升级。 | 原有记录、未发队列、照片、目录授权与已配置的密钥仍可用。过期或授权失效时能按提示恢复，恢复前保留本地副本。自动续签另按一周实测记录。 |
| 两端离线修改同一餐，一端删除另一端编辑，再交换两端收到文件的顺序。 | 两端最终看到同一冲突，合并结果一致。故意重放旧操作不会产生重复或复活记录。 |
| 一次选 8 张照片，让附件晚到，模拟部分下载、磁盘或 iCloud 空间不足，再恢复空间重试。 | 能辨认哪几张未完成，文字和草稿可读，补齐后顺序和哈希一致。其他记录仍能同步。 |
| 用旧快捷指令录入后重扫，再对同一批历史样例迁移两次。加入 03:59、04:00 和跨零点步数样例。 | 记录数和图片数与清单相同。原编号不变，手记按凌晨四点换日、步数按自然日归属，两端日期一致。 |
| 撤销目录权限、选错档案、以空安装恢复密钥，再执行一次停用回退。 | 本地仍可打开和编辑。错目录不混入记录。正确配对后可续传，恢复的照片可验。启用加密后，共享目录中的样例正文和照片均为密文，仅本机类别没有待发操作。 |

每个涉及代码的阶段运行现有 `npm test`、`npm run build`。同步新增同一组合成样例供 TypeScript 和 Swift 回放，覆盖重复操作、错序、损坏附件和并发编辑。目录授权、iCloud 传送及 AltStore 续签以真机结果为准。

第一阶段的交付物是一份可侧载的测试 IPA、Mac 演示入口，以及餐食往返和手动续签的真机记录。届时即可判断这套方案在自己两台设备上的实际体验。
