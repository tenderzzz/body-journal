# 开始使用

[返回首页](../README.md) · [全部文档](README.md)

## 1. 安装 Mac 应用

当前发布包支持 **macOS Apple Silicon（arm64）**，界面为中文。先通过苹果菜单“关于本机”确认芯片类型；仓库没有提供 Intel Mac 或 Windows 安装包。

1. 打开 [最新 Release](https://github.com/tenderzzz/body-journal/releases/latest)，下载 `body-journal-mac-arm64.zip` 和 `SHA256SUMS.txt`。
2. 在下载目录打开终端，执行 `shasum -a 256 body-journal-mac-arm64.zip`，与**同一个 Release** 的校验值核对。
3. 解压，将 `身体手记.app` 拖入应用程序目录后打开。
4. 本项目使用 ad-hoc 签名，未经 Apple Developer ID 公证。若系统拦截，可先尝试 Finder 右键应用 →“打开”；若仍被拦截，在“系统设置 → 隐私与安全性”查看对应的“仍要打开”选项。系统版本不同，提示可能有差异。

发布包由 GitHub Actions 从版本标签的干净检出构建；快捷指令仅包含未签名源文件。

## 2. 先完成一条本地记录

暂时不连接模型也能使用本地记录。

1. 在“记录”新增一条测试内容，例如“今天散步半小时”；检查日期与类型。
2. 打开详情，确认原文；尝试修改、撤销，再删除或恢复这条测试记录。
3. 在“我的档案”填写希望长期使用的偏好或目标。没有确定的营养目标时可以留空。
4. 训练笔记可在“记录 → 导入笔记”粘贴；有歧义的重量和组次请在详情核对。

保存原文和图像与模型分析是分开的操作。需要结构化分析时，再完成模型连接。

## 3. 按需连接模型

应用内置 ChatGPT 授权与 DeepSeek API 适配。实际账号资格、可用模型、额度和单价由服务商决定；自动测试不代表真实账号一定可以连接。

**ChatGPT**：在“连接与数据”点击 `Continue with ChatGPT`，在浏览器完成授权；回到应用刷新并选择账号可用模型，保存设置，再测试连接。若授权或模型目录不可用，可以继续本地记录。

**DeepSeek**：在同一页面选择对应服务，填写自己的 API 密钥并点击“保存密钥”；再填写月预算与单价，点击“保存连接设置”后测试连接。默认月预算为 0，设置为正数后才会发出请求。费用是按配置计算的本应用估算，不能限制其他应用的消费；不会在 ChatGPT 不可用时自动切换过去。

“测试图文连接”会发送应用自带的示意图；聊天、分析和能量问答会发送该操作所需的记录、相关上下文和图片。详见 [隐私与数据](privacy.md)。

## 4. 连接 iPhone 快捷指令

手机入口是 Apple 快捷指令，不是独立的 iPhone App。需要在两台设备上启用自己的 iCloud Drive。

1. 在 Mac 应用“连接与数据”点击“建立并打开收件箱”。默认位置是 iCloud Drive 的 `Shortcuts/BodyJournal/inbox`。
2. 按 [快捷指令安装说明](../shortcuts/开始安装.md) 在 Mac 用自己的 Apple 账号签名四个快捷指令，再传到 iPhone 安装。仓库的 `shortcuts/unsigned/` 文件不能直接导入。
3. 安装时，为四个入口都选择同一收件箱。相机、照片和文件夹权限由系统首次使用时询问。
4. 先用“随手记”写一句不含隐私的测试文字；看到“已保存”后，等待 iCloud 同步，并检查 Mac 导入结果。

| 入口 | 建议记录 |
| --- | --- |
| 记一餐 | 照片或菜名、大概分量、剩余量 |
| 记训练 | 动作、kg、组次、实际时长；也可记录运动 App 截图 |
| 记身体 | 体重、腰围等测量 |
| 随手记 | 睡眠感受、疲劳、生活状态与补充说明 |

每次保存生成一条带独立编号的 JSON 记录，文字与图片在同一文件中。手机提示保存成功不表示另一台设备已经收到；Mac 应用需运行才能导入收件箱。

## 5. 使用能量页

1. 在“能量”补充计算资料：年龄、身高、公式性别参数、日常活动与常规训练安排；体重沿用已确认测量。
2. 核对生效日期和资料。历史日期使用当时已生效的资料与可用记录，缺失时会提示。
3. 设定维持、减脂或增肌目标。参考值只用于帮助填写，点击确认才生效；已有手填目标优先保留。
4. 填写当天的活动信息。完整步数会扣除跑步重叠，再与手动／历史／暂定参考比较；不完整或冲突的数据会单独说明。
5. 确认确实记齐后，再勾选饮食、活动核对。页面区分“你已核对”和“估算资料是否完整”。

全天预计消耗与当前已记摄入不是同一时间口径。漏记的餐食不会按零处理；不要直接把“目标减已记摄入”当成还能吃多少。详细公式、步数假设和调整门槛见 [能量估算说明](能量估算说明.md)。

## 6. 备份、导出与升级

在“连接与数据”使用完整备份和恢复功能；可读导出用于自行查阅。完整备份包含修订历史与附件，**不包含模型凭据，也没有应用层加密**，请放在自己控制的位置。

升级前建议手动保存一份完整备份。v0.4.0 的数据库与备份格式为 v3，支持恢复 v1／v2 备份；迁移前会自动备份。旧版本不应直接打开升级后的数据库；需要回退时使用对应的旧版备份。

不要在应用运行时只复制 `health.sqlite` 当作完整备份。卸载 `.app` 不会自动删除本机档案、收件箱或其他位置的备份。数据位置和软删除行为见 [隐私与数据](privacy.md)。

## 常见问题

**没有连接 AI，哪些功能还能用？** 保存和编辑原始记录、导入、查看已有结构化结果、本地计算与趋势、导出与备份。新图文理解和问答需要模型连接。

**手机显示已保存，Mac 还没看到？** 核对两端是否指向同一个 iCloud 文件夹、文件是否已完成下载、Mac 应用是否正在运行。先用合成测试文字重试。

**为什么热量是区间？** 原料、分量、活动档位和时长都有不确定性；区间表示输入假设，不是统计置信区间或实测精度。

**修改记录后，旧回答为什么失效？** 回答依赖原来的记录版本。依据变化后标记旧回答，可以避免把旧结论当成对新记录的判断。

**为什么不能直接安装仓库里的快捷指令？** 公开的是未签名源文件；请按安装说明自行签名。不要公开上传自己生成的签名文件。

**从源码如何看示例？** 使用 [首页的示例模式命令](../README.md#从源码运行)。根目录的 `查看示例.command` 需要先打包，且可能更新 `~/Applications` 中的应用；具体见 [开发说明](development.md)。

仍有问题时，请使用 [问题反馈模板](https://github.com/tenderzzz/body-journal/issues/new/choose)，写明版本、系统、步骤和脱敏示例，不要附上真实档案、照片或密钥。
