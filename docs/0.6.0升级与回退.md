# v0.6.0 升级与回退

本版面向单人长期使用，增加按话题跨对话接续、带时间的记忆、按发生日期查账，以及可以保存大照片档案的完整备份。

## 升级前与第一次启动

退出正在运行的身体手记，保留原来的应用包，然后打开 v0.6.0。第一次写入旧档案之前，应用会在主档案旁建立 `vault-before-v06-时间-编号` 目录，保存旧版本 SQLite 一致性副本、原文、照片和 `rollback.json` 校验清单。旧数据库版本仍保留在这个目录里。空间不足或原图校验失败会中止启动，释放空间或修复附件后可重试。

默认档案位于 `~/Library/Application Support/BodyJournal/vault`，回退副本位于同一个 `BodyJournal` 目录下。迁移会在本机整理已有日期与证据，整理本身不调用模型。

## 使用时可以怎样核对

- 新对话仍可承接相关近期安排。明确说“这周”的约定以档案时区的周日结束为止。短期线索前三天保留相关原话，此后优先提供带日期的简述，十四天后通常需要主动追问。
- 可以问“6月10日肩推做了几组”或“上周训练”。回答下方的“本次参考与引用”可查看查询时段、提供的记录数量和实际引用的记录。
- 更正偏好会更新现行约定。旧说法保留为有时间的历史。习惯需要独立日期的支持，重分析同一张照片不会增加依据或营养精度。
- 聊天中讨论的训练计划与完成日志分开，实际训练仍从记录入口入档。

## 备份与换机

“连接与数据 → 保存完整备份”生成 v5 单文件 SQLite 容器，扩展名仍是 `.bodyjournal`。图片逐块保存，支持超过旧 512 MB 上限的档案。完整备份包含修订、话题依据、训练归档和计重规则、食物候选偏好及能量历史。凭据由本机系统保护，恢复时保留目标机器的账号与收件箱路径。备份未加口令，请放在自己控制的位置。

选择恢复文件后，应用先在同一磁盘的临时目录验证数据和原图，再保存当前档案的安全备份并切换。恢复前备份名为 `vault.before-restore-时间.bodyjournal`，旧目录保留为 `vault.previous-编号`。遇到切换中断，下次启动会检查恢复标记，优先找回完整档案。v1–v4 JSON 备份继续可以导入，旧备份没有保存的偏好使用默认值。

## 回到升级前

回退对应第一次升级时的记录。先在 v0.6.0 保存一份新的完整备份，保留升级后的新增资料，然后退出应用。将当前 `vault` 目录改名保存，把选定的 `vault-before-v06-…` 目录复制成 `vault`，再打开与旧库对应的旧版应用。保留升级后的 v5 备份，日后可用 v0.6.0 恢复。

原始副本和安全备份均由你保管。回退前确认目录名称，恢复操作通过应用完成，复制数据库只用于应用已退出且具有完整照片目录的升级前回退点。

## 本版验证范围

自动回放使用固定时点、合成档案和两种渠道的模拟流式回答，核对实际请求材料、引用与持久化状态。大档案验证使用约 540 MB 的合成图片数据。桌面验证检查实际安装包的更正、新对话、历史查询、完整备份恢复与重启。真实模型的自然程度通过日常主动对话继续观察，模拟测试只证明材料选择、规则与保存流程。
