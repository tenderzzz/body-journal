# 数据与隐私

身体手记将健康档案保存在 Mac，本地完成导入、趋势统计、营养合计与能量计算。iCloud 负责手机收件箱同步；你主动分析或提问时，相关内容会发送给所选模型服务。

本文对应公开源码的实际行为，便于你决定记录什么、连接哪个服务，以及如何备份和分享问题。

## 数据保存在哪里

| 内容 | 默认位置 |
| --- | --- |
| 本地主档案 | `~/Library/Application Support/BodyJournal/vault/` |
| SQLite 数据库 | 主档案内的 `health.sqlite`（运行时还可能有日志文件） |
| 最初导入的原文与图片 | 主档案内的 `raw/`、`attachments/` |
| 升级、恢复和记忆整理前的自动备份 | 主档案内的 `backups/` |
| 模型凭据 | `~/Library/Application Support/BodyJournal/credentials.enc` |
| 手机收件箱 | `~/Library/Mobile Documents/com~apple~CloudDocs/Shortcuts/BodyJournal/inbox/` |
| 手动备份与可读导出 | 由你在保存对话框选择 |

收件箱可以在“连接与数据”中更换。主数据库默认不放在 iCloud，收件箱中的 JSON 则可能同时包含原文与照片，属于健康数据的一份副本。

档案采用普通 SQLite 和文件存储，**没有应用层加密**。凭据通过 Electron `safeStorage` 使用 macOS 的系统保护机制加密保存；系统保护不可用时，不会退回明文保存密钥。这与整个健康档案加密是两回事。

## 哪些操作会联网

| 操作 | 数据流向 |
| --- | --- |
| iPhone 快捷指令保存、跨设备收件箱同步 | iCloud Drive / Apple；快捷指令本身不调用模型、不含模型密钥 |
| 本地导入、修改记录、查看趋势、计算营养和能量 | 本机处理，不需要模型请求 |
| Continue with ChatGPT、刷新模型目录 | OpenAI 授权及模型服务；授权凭据保存在本机受保护的凭据文件中 |
| 分析记录、分析待处理记录 | 当前选用的 OpenAI 或 DeepSeek 服务 |
| 活动截图中的“保存并提取”“重新提取” | 先保存本地记录，再向所选模型服务发送提取请求；手动更正活动数值在本机完成 |
| 助理对话、周复盘、能量页问答 | 当前选用的 OpenAI 或 DeepSeek 服务 |
| 测试图文连接 | 所选模型服务；发送应用自带示意图及测试文字 |
| 打开外部资料链接 | 系统浏览器访问相应网站 |

收件箱会定期在本地扫描，但不会因此自动分析。模型请求由你的操作触发；请求需要时可能同时刷新授权凭据。应用不会在模型失败后自动改用另一个付费服务。

## 模型看到什么

**分析记录会附带理解这条记录所需的参考信息，并非只发送选中的一段文字。** 当前实现可能包含：

- 该条记录的原文、日期、身体数值、已有食材，以及最多 4 张图片。
- 与分析相关的个人记忆、已确认的常用食物标签和食材目录。
- 餐食分析中的最近最多 40 条已分析餐食摘要，用于查找“和上次一样”的餐食；包括日期、原文片段、食材与部分营养数据。
- 训练分析中的已配置训练偏好与指导规则。

图片会在发送前转换为 JPEG、将最长边限制为 1,600 像素；原图仍保存在本机。

活动截图还可能提取运动 App 名称、运动编号、心率、步数、步频、时长与热量口径，并作为分析结果保存在记录里。手动更正会保留修订历史。当前没有直接连接 Apple Health 或运动 App 账号，数据来自你导入的文字和图片。

**对话会附带检索得到的上下文**，可能包括近期及关键词相关记录、已有分析、目标、个人记忆、相关历史对话，以及本地生成的训练或能量统计。记录检索通常覆盖最近 35 天，月度问题扩至 90 天，历史类问题可检索更早记录，最多 160 条；能量问题还可能补充计算所依据的记录。并非每次对话都会上传全部档案。

应用向 OpenAI 发送的推理请求设置了 `store: false`。这只是请求参数，不能据此承诺服务商不保留任何日志、不用于任何用途，或提供端到端加密。服务商的数据处理、账号资格与额度以其当前政策为准。

## 备份、修改与删除

- 在“连接与数据”使用完整备份，可以保存记录、修订历史、记忆、对话、能量资料和原图。凭据不随完整备份导出，恢复不会覆盖账号密钥。
- 当前数据库与完整备份格式为 v3，兼容恢复 v1 / v2 备份；活动提取字段、手动更正、步数参考资料与核对状态也属于备份中的个人数据。较旧应用不一定能读取新档案，回退前请保留升级前备份。
- `.bodyjournal` 是包含数据和附件的 JSON 备份，**没有加密**；Base64 只是图片编码。可读导出同样包含原文、图片与个人资料。
- 修改记录会保留最初导入的原文和修订历史。“删除记录”是可恢复的软删除，不是彻底擦除；已生成的备份、导出和 iCloud 收件箱也不会随之删除。
- 在本机删除数据不会撤回已经发给模型服务的内容，也不会清除其他设备、云端或系统备份中的副本。
- 不要在应用运行时仅复制 `health.sqlite` 作为完整备份；请使用应用内备份功能。目前完整备份大小上限为 512 MB。

## 截图和问题反馈

公开 Issue 和 Pull Request 对所有人可见。请优先使用“查看示例”模式或自编的测试记录，遮盖账号、姓名、真实健康记录、私人文件路径和照片中的个人信息。不要上传 `credentials.enc`、数据库、完整备份、真实收件箱 JSON 或已签名快捷指令。

示例模式与自动测试使用独立档案。仓库 `evidence/` 中的界面截图使用合成示例数据。

发现可能导致隐私泄露的漏洞，请按 [安全问题反馈](../SECURITY.md) 处理。安装和日常使用见 [README](../README.md) 与[使用说明](使用说明.html)。
